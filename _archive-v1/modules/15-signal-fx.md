# 模块：信号层视觉效果

> 上位：`docs/BRIEF.md` C8（零美术资产、emoji 即视觉层）、
> `docs/content/authoring.md` §1.5（三个声音）。

## 1. 信号层是第三个声音

`authoring.md` 原本只有两个声音：叙述层（摄像机，零评价）与观众层（刻薄，有观点）。
视觉效果无处安放——"文字突然变红"严格说是叙述者在表态，违反零评价。

**归属是：它不是叙述者在表态，是信号出问题了。**

这个游戏的框架是"你的人生是一部剧，分数是收视率"。
所以恐怖不表现为"叙述者害怕了"，表现为**播出信号劣化**：
掉色、掉帧、字符错位、雪花。观众正在看的那台电视出了问题。

| 层 | 声音 | 表达方式 |
|---|---|---|
| 叙述层 | 摄像机 | 零评价的文字 |
| 观众层 | 刻薄 | 短评、评分、标签 |
| **信号层** | **没有观点，只会故障** | 变色、破碎、抖动、粒子 |

**信号层永远不评价，它只是坏掉。**

所以租到闹鬼房间那条事件的**文字本身**仍然冷静客观：

```
房东说这间以前也租过人。押一付三，他没说付几个月。
```

字是冷的，信号在抖。这比"你感到一阵寒意"强得多，
而且它让 `authoring.md` §8 的禁用词表继续全额生效。

## 2. 三类效果

### 2.1 变色 / 色差（成本最低）

CSS 自定义属性 + class 切换：

```css
.stage { --ink: #e8e4dc; --bg: #14131a;
         transition: color .18s, background .18s; }
.stage.sig-bad {
  --ink: #c8352f;
  text-shadow: 1px 0 #0ff, -1px 0 #f0f;   /* 色差，像信号串色 */
}
```

逐字变色把文本拆成 `<span>`，Vue 直接渲染。
**推荐做法是"从第 N 个字开始变色"**——句子说到一半信号才出问题，
比整段变色瘆人得多。

glitch 不需要图片：两层 `text-shadow` 偏移 + `clip-path` 逐帧切片位移，纯 CSS 关键帧。

### 2.2 文字破碎

三条路，按成本递增：

| 路 | 做法 | 适用 |
|---|---|---|
| **A 逐字 transform** | 拆 span，每个给随机 CSS 变量，关键帧各自飞散 | 常规破碎。60 字以内手机稳 60fps |
| **B canvas 像素采样** | 文字画到离屏 canvas，`getImageData` 逐像素采样，每个非透明像素生成方块粒子 | 仅关键恐怖节点 |
| **C mask 溶解** | `background-clip: text` + 渐变遮罩动画 | "字被吃掉"而不是炸开 |

A 路示例：

```html
<span style="--dx:-24px;--dy:38px;--rot:-31deg">房</span>
```

> **`file://` 关键细节**：canvas 污染只由跨域图片引起，
> 自己画的文字不会污染，所以 `getImageData` 在本地双击打开时正常可用。
> **我们没有图片资产这件事在这里反而是优势。**

B 路开销：60 字按每 3px 采样约 800–2000 粒子。桌面轻松，手机必须限量（见 §3）。

### 2.3 像素粒子（小丑牌手感）

小丑牌的爽感拆开是四件事：

| 要素 | 做法 |
|---|---|
| 数字弹出过冲 | CSS 关键帧 `scale: .6 → 1.25 → 1`，`cubic-bezier` 回弹，颜色按量级升档 |
| 屏幕震动 | 外层 wrapper 的 `transform: translate`，衰减随机走 |
| 块状像素粒子 | 单 canvas，`fillRect` 画**方块**，整数坐标，6 色调色板 |
| 拖影 | 每帧用低 alpha 填充而不是 `clearRect` |

**为什么看起来像像素**：粒子是方的、坐标取整、颜色只有几种、不抗锯齿。
用 `arc()` 画圆会立刻变成通用粒子特效，那个味道就没了。这条是硬要求。

**emoji 可以直接当粒子画**（`ctx.fillText`）：恐怖 🩸，爆分 ✨，修仙 ⚡。
零图片资产，完全符合 C8。

## 3. 工程约束

不写进架构就会后期返工：

| 约束 | 说明 |
|---|---|
| **一个全局 canvas** | 整个 app 只有一层，`pointer-events: none`。不要每组件一个 |
| **对象池 + 硬上限** | 手机 600，桌面 1500。超限复用最老的，不做无上限分配 |
| **空闲停 rAF** | 没粒子就不跑循环，不烧电池 |
| **DPR 上限 2** | 某些安卓 `devicePixelRatio` 是 3–4，画布面积翻 4 倍直接掉帧 |
| **引擎不碰 DOM** | 引擎只发数据，UI 决定视觉 |

最后一条是 `09-vertical-slice.md` §3 的硬要求。引擎发的是：

```js
{ kind: 'scorePop', value: 857, chain: 3, tone: 'sig-bad' }
```

UI 层自己决定怎么演。这样引擎仍能在 node 里批量跑 1000 局调参，
`document` 一次都不出现。

信号效果通过 `BH.define.signalFx(name, spec)` 注册（`14-content-api.md` §5.1），
事件数据里只写效果名，不写实现。

## 4. 节奏红线

容易被忽略但很致命：**熟练局目标时长内，平均每脉冲只有 3–4 秒。**

- 单次动效 **≤ 400ms**（小丑牌的 juice 也都在 300ms 以内）
- 信号劣化可例外到 **800ms**
- **点击必须能打断动效**，不能等播完
- 动效永不阻塞输入，永不做成强制路径

## 5. 无障碍

两条必须守：

- `prefers-reduced-motion: reduce` 时关掉抖动与粒子，**保留变色**
- **颜色不能是唯一的信息载体**。信号劣化必须同时有非颜色线索
  （字符错位、字重变化、标点异常），否则色觉障碍玩家完全接收不到

> 完整 WCAG 合规需要辅助技术实机测试与专家评审，本节只保证这两条基本项。
