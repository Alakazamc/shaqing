# 模块：结算后抽卡

> 上位：`docs/SYSTEM.md` §6（meta）、`docs/BRIEF.md` C6（传播是一等需求）。
> 本模块**替代**原先的"素材商店"设计，`06-meta.md` 同步更新。

## 1. 为什么是抽卡

每局结束必有一次开箱，`再来一局` 的钩子从"我想试试别的构筑"（软）
变成"我想看看抽到什么"（硬）。

抽卡还接上了传播链：抽到 T3 离谱内容的截图本身就是转发素材（`C6`）。

## 2. 核心设计：抽卡池按本局剧情加权

**这是本模块唯一真正重要的设计，其他都是参数。**

```
你这条命：中专 → 鼠鼠 → 修仙，遇到过 🧓 下棋的老头

抽卡池权重偏向 → 仙侠圈层内容 / 职校圈层内容 / 山野系 NPC
```

理由：这样抽卡是"**这条命留下的遗产**"，而不是一台和刚才那局无关的老虎机。
想解锁仙侠内容就去走仙侠。

它顺手解决了一个反刷分问题：**按分数解锁会逼玩家刷同一套构筑**，
而主题池奖励换路线，与 `F` 疲劳系数（`SYSTEM.md` §2）的意图同向。

## 3. 规则

数值均为待调参初值。

| 项 | 规则 |
|---|---|
| 抽卡次数 | 每局固定 **1 次免费**，素材可加抽 |
| 档位 | 池分 T1/T2/T3，评分**提高 T2/T3 权重**，不是解锁门槛 |
| 主题倾斜 | 本局主导轨道 + 出场 NPC 的圈层加权 ×3 |
| 重复保护 | 抽到已解锁的转成素材，并提高下次高档权重（软保底） |
| 保底通道 | 素材可**定向解锁**指定内容 |

### 3.1 为什么用"提高权重"而不是"到分才解锁"

用门槛的话，低分玩家永远看不到 T3，而低分是这个游戏的默认状态
（`SYSTEM.md` §3.4：默认玩家落在 3–5 分）。那会让绝大多数玩家
感觉内容被锁死，与"再来一局成本为零"矛盾。

权重制下每个人都有机会摸到 T3，只是高分玩家概率更高。

### 3.2 定向解锁是防挫败的

抽卡是快车道，素材定向解锁是**保证到货的慢车道**。
不会有人因为运气卡死在某个想要的内容上。

这条不能省。纯抽卡会产生"我抽了 20 局还没出那条轨道"的挫败，
而这个游戏的整个留存逻辑建立在"再来一局是愉快的"。

## 4. 三条红线

1. **只解锁内容，永不解锁数值强化。** 与 `SYSTEM.md` §6 一致——
   否则老玩家和新玩家的截图不可比，`C6` 的传播链断掉。
2. **T3 的"高级"是更离谱，不是更强。** 见 `11-origin.md` §9。
3. **真结局不进抽卡池，不被任何抽卡结果暗示。** 见 `08-true-ending.md` §7。
   抽卡界面不得出现任何指向它的空槽、计数或提示。

## 5. UX 顺序：抽卡在结算页之后

```
死亡 → 结算页（分享时刻）→ 抽卡（下一局的钩子）→ 再来一局
```

顺序反了会让抽卡动效抢掉截图那一下。结算页是**产品本体**
（`07-settlement.md` §1），抽卡是附加的前向钩子，不能盖过它。

实现约束：抽卡界面必须能**一键跳过**直接开下一局。
熟练玩家的目标局时长是 100–150 秒（`SYSTEM.md` §1.2），
抽卡动画不能是强制路径。

## 6. 可抽内容类型

| 类型 | 说明 |
|---|---|
| 家庭项 | T1–T3，见 `11-origin.md` §9 |
| 性格项 | 同上 |
| 特质（天赋） | 进天赋三选一池 |
| 人设牌 | **进池**，不是直接发牌 |
| NPC | 让某个 NPC 有机会在后续局出场 |
| 轨道 | 解锁某条隐秘轨道的**起点权限** |

"进池"而不是"发牌"这个区别很重要（`SYSTEM.md` §6）：
解锁扩大的是**构筑空间**，不是构筑强度。

## 7. 数据结构

```js
// content/gacha.js
{
  id: 'g_npc_qishou',
  type: 'npc',              // family | personality | talent | cast | npc | track
  target: 'npc_qishou',     // 解锁的目标 id
  tier: 2,                  // 1 | 2 | 3
  scopes: ['xianxia'],      // 主题倾斜用：与本局圈层匹配则权重 ×3
  weight: 10,               // 基础权重
  dupValue: 12,             // 重复时转化的素材量
}
```

## 8. 一致性检查

补进 `content/README.md` §5：

1. 每个抽卡条目的 `target` 存在于对应内容表中
2. 每个 `scopes` 值都在 `tracks.js` 的 `lexiconScope` 枚举内
3. T2 / T3 的每个内容项都**恰好**被一个抽卡条目覆盖（无重复、无遗漏）
4. 抽卡池不含 `type: 'ending'` 的任何条目（真结局红线）
5. 每个条目 `dupValue > 0`（重复必须有转化，不能空手）

## 9. 分期

- **A 期**：抽卡系统骨架、主题池加权、重复保护、定向解锁，池内 **12 条**
- **B 期**：池铺满，覆盖 `content/README.md` §4 首发列的全部内容


## 任务 #7：抽卡解锁真正改变后续可能性

抽卡条目继续只解锁内容，不直接给数值。写入 `save.unlocked` 后，下一局通过
`run.create({ meta: { unlocked } })` 获得内容快照：已解锁天赋参与一个稳定的 seed
开局档案位，已解锁人设牌优先进入季末人设奖励池，已解锁轨道/NPC 的档案节目牌
进入路线 offers。基础内容不被锁死，未解锁状态仍能完成首局。

抽卡池在同一账号内优先选择尚未解锁的条目；全部条目都已解锁时才回退到重复抽卡，
重复仍按 `dupValue` 转素材。评分只影响 tier 权重，路线/NPC 只影响主题权重，元进度
只影响内容可见性，三者不能互相伪装成数值强化。
