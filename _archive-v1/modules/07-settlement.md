# 模块：结算页、剧名生成、分享卡

> 上位：`docs/BRIEF.md` C6 C8、`docs/SYSTEM.md` §3.4。

## 1. 结算页即主界面

C6 的硬要求：不是做完游戏再加分享按钮。**结算页是这个游戏的产品本体**，
每局必须产出一件值得截图的畸形作品。

形态是**豆瓣式条目页**。选它的理由：中文互联网没人需要教就懂这张图，
零解释成本地传达"这是一部剧、它被打了分、评分很低很好笑"。

```
┌─────────────────────────────┐
│ 《我在中专修仙的那些年》      │
│ 2003–2041 · 大陆 · 荒诞/励志  │
│                             │
│        6.0                  │
│      ★★★☆☆  4831 人评价      │
│                             │
│ 标签  注水  抽象  修仙  暴富   │
│                             │
│ 剧情简介                     │
│ 中专辍学后他上山学道，靠直播  │
│ 抽象爆红，赔光积蓄，最后死于  │
│ 一场荒诞的电梯事故。          │
│                             │
│ 高光时间线                   │
│ 17岁 退学          收视 42    │
│ 23岁 直播翻车爆红   收视 8600  │
│ 31岁 赔光积蓄       收视 1.2万 │
│ 38岁 电梯事故       收视 3.1万 │
│                             │
│ 人设                        │
│ 🤡抽象怪 lv2  🧘筑基  💧注水  │
│                             │
│ 总收视 11.6 万 · 振幅×2.8    │
│ 贯彻×2.1 · 反讽×2.5          │
│                             │
│ 短评                        │
│ "前期挺有意思，后面就为了      │
│  流量硬演了" — 观众           │
│                             │
│ seed 8F3K2Q  ·  你也来一局    │
└─────────────────────────────┘
```

两个数字都要在：**豆瓣式低分负责"笑死"的转发，总收视量级负责小丑牌式的构筑炫耀。**

> 样例里的数字必须与 `SYSTEM.md` §3.4 的映射自洽：
> `2.0 + 1.5 × log₁₀(116000/2000) ≈ 4.6`。
> 4.6 属于"构筑成型"区间，实测 random 默认局中位数约 3.6，greedy 约 5.0，默认玩家落在 3–4 分。
> 标签取 `注水` 而非 `烂尾`：本局只被腰斩过一次，
> 而 `烂尾` 只在第二次腰斩后挂上，本局仍继续注水并播到 S5（`05-chapter.md` §3）。
>
> 修订记录：初版写的是 `3.1 分 / 总收视 41.2 万`，两个数字既互不自洽、
> 也与高光时间线的单年收视之和矛盾。随后曾用 pivot 250 做过过渡样例；
> 当前内容量回到 pivot **2000**，因此样例固定为 `4.6 / 11.6 万`，
> 时间线各年数值不因评分映射改变。

## 2. 剧名生成

剧名是截图的第一钩子，必须每局不同且读起来像真剧名。用槽位语法组合：

```
《我在{地点}{行为}的那些年》
《{形容}{身份}》
《{行为}到{结局}》
《我，{身份}，{转折}》
```

槽位取值来自本局的实际轨迹（轨道 + 最高收视事件 + 死法），不是随机词表：

| 槽位 | 来源 |
|---|---|
| `{地点}` | 首个主导轨道的场景标签（中专 / 网吧 / 山上 / 直播间）|
| `{行为}` | 最高收视年事件的动词标签 |
| `{身份}` | 主导轨道 + 深度（`修仙者` / `半仙` / `野生道士`）|
| `{转折}` | 振幅最大那一段的方向（暴富 / 赔光 / 塌房）|
| `{结局}` | 死法事件的标签 |

生成规则：**优先选包含反差的组合**。`我在中专修仙` 好过 `我的修仙生涯`，
因为反差是转发理由。实现上给每个候选算一个"反差分"
（两个槽位的圈层标签距离），取最高的。

## 3. 短评生成

短评属于**观众层**（`content/authoring.md` §1.5），因此它**不受叙述层的
零评价规范约束**——恰恰相反，它就是要有观点、要刻薄。

游戏的态度全部住在观众层和数学里，叙述层一句不表态。
所以"事件正文冷静客观"与"短评刻薄"不是矛盾，是两个不同的声音。

短评是"观众"口吻，且必须**刻薄而不是总结**。按本局特征匹配模板：

| 触发特征 | 短评方向 |
|---|---|
| `Amp` 低 + 高分 | "太顺了，没戏" |
| `Com` 被罚到 0.5 | "编剧自己都不知道要讲什么" |
| 有 `注水` 污点 | "第二季开始就在硬撑" |
| `Iro ≥ 2.5` | "结尾还行，前面白熬了" |
| 烂尾标签 | "开高走低，建议直接看解说" |
| 收视极高 | "看完了，但我不推荐任何人看" |

短评**永远不夸玩家**。这是 C3 的延伸：游戏的评价体系本身是荒谬的，
它只关心好不好看，而且它嘴很碎。

## 4. 分享卡导出（C8）

零美术资产，全部 Canvas 绘制：

- emoji 直接作为图标绘制（`ctx.fillText`），跨平台自带语义
- 字体只用系统字体栈，不加载 webfont
- 竖版 `1080 × 1920`，手机截图比例
- 导出 PNG：`canvas.toBlob()` → 下载 / 复制到剪贴板
- **不上传任何数据**，纯本地生成（C8 不依赖网络）

降级：`toBlob` 不可用时提示玩家直接截图。分享卡是加分项，
不能因为它失败而阻塞"看到结算页"这件事。

## 5. 真结局的结算页（C7）

真结局的结算页是**同一套布局的残缺版本**，这个对比本身是设计：

```
┌─────────────────────────────┐
│ 《（无题）》                  │
│                             │
│         —                   │
│      暂无评分                │
│                             │
│ 标签  （无）                  │
│                             │
│ 剧情简介                     │
│ 已下架                       │
│                             │
│ 高光时间线                   │
│ （无高光）                    │
│                             │
│ 人设                        │
│ 🤡抽象怪 lv2  💧注水  🩹破罐  │
│                             │
│ 短评                        │
│ （无人评价）                  │
└─────────────────────────────┘
```

要点：

- 评分位显示 `—`，不是 0.0。**框架脱落，不是得零分**
- 人设牌与污点牌**一张不少地照常显示**。你没被洗白，你只是不演了
- 没有任何"恭喜""真结局""隐藏成就"字样
- 分享卡照常可导出。这张卡的传播力恰恰在于它看起来像 bug

## 6. 结算页的验收标准

C6 是一等需求，所以结算页有硬验收（进 `09-vertical-slice.md`）：

1. 任意一局结束后 **3 秒内**看到完整结算页，不需要滑动就能看到剧名 + 评分 + 标签
2. 剧名在 100 次不同 seed 的跑局里重复率 < 5%
3. 短评与本局特征匹配，不出现"高分局配'太顺了没戏'"这类矛盾
4. 分享卡 PNG 在移动端竖屏一屏内可读（字号下限 28px @1080 宽）

## 6.1 当前运行时的分数去向

纵切片阶段把分数用途固定成一条可读链路，不新增第二套评分：

```text
每次年度收视（B × M × A × F）
  → 累加本季收视 / 续订线
  → 续订、加更或腰斩
  → 终局总收视 × Amp × Com × Iro
  → 豆瓣式观众评分 + 素材
  → 结算后一次抽卡：评分影响档位，路线/NPC 影响主题权重
  → 新抽卡写入解锁记录，重复结果转为素材
```

玩家在日志中看到本次 `B/M/A/F`，HUD 看到本季收视与续订线，季末看到结果对下一季的影响，结算页看到总收视、三乘数、评分和本局素材来源，抽卡页看到评分/路线怎样影响这次遗产。

当前 A 期素材为：总收视的对数换算（最低 5）+ 首次发现轨道 20 + 首次结局 15 + 经历腰斩 5；重复抽卡的 `dupValue` 另行加入素材。解锁记录已经保存，但按解锁过滤开局池和事件池属于后续元进度阶段，不能在当前 UI 中伪装成已完成。

## 7. 与抽卡的顺序关系

```
死亡 → 结算页（分享时刻）→ 抽卡（下一局的钩子）→ 再来一局
```

**抽卡必须在结算页之后**，顺序反了会让抽卡动效抢掉截图那一下。

结算页是产品本体（§1），抽卡是附加的前向钩子，不能盖过它。
抽卡界面必须支持**一键跳过**——熟练局目标时长 100–150 秒
（`SYSTEM.md` §1.2），抽卡动画不能是强制路径。

详见 `12-gacha.md` §5。
