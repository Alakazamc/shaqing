# 模块：meta 进度与图鉴

> 上位：`docs/SYSTEM.md` §6、`docs/BRIEF.md` C6。

## 1. 货币：素材

结算按总收视产出 **`素材`**：

```
素材 = max(5, floor( 10 × log₁₀(总收视 + 1) )) + 结局奖励 + 首次发现奖励
```

| 来源 | 数值 |
|---|---|
| 收视换算 | 总收视 2 000 → 33；200 000 → 53；2 000 000 → 63 |
| 首次发现轨道 | +20 每条 |
| 首次达成结局 | +15 每个 |
| 腰斩完结 | +5（保底，绝不空手）|

对数换算保证**烂局也有收益**（C6：再来一局成本为零），
同时让高分局的边际收益递减，避免刷同一套构筑。

## 2. 解锁走双轨

**快车道：结算页之后抽一次卡**（`12-gacha.md`）。
**慢车道：素材定向解锁**指定内容，保证到货，防止运气卡死。

可解锁的只有六类：

| 类别 | 内容 | 明确不做 |
|---|---|---|
| 人设牌进池 | 让某张牌**有机会出现** | 不直接发牌给玩家 |
| 开局天赋池扩容 | 保留原作的天赋三选一 | 不提供天赋重抽次数购买 |
| 家庭 / 性格项 | 开局四项的选项，分 T1–T3 | 不解锁属性初始值加成 |
| NPC 进池 | 让某个 NPC 有机会出场 | 不解锁"必定遇到某人" |
| 轨道起点权限 | 隐秘轨道的入口资格 | 不解锁轨道内的数值 |
| 图鉴与统计 | 轨道 / 结局 / 人设收集 | — |

**明确不解锁任何数值强化。** 理由是传播链：
如果老玩家的分数天生更高，新玩家的截图和老玩家的截图不可比，
"我的人生 3.1 分"这句话就失去共同基准，C6 断掉。

"进池"而不是"发牌"这个区别很重要：它让解锁扩大的是**构筑空间**，
不是构筑强度。每局仍然在同一套公式下公平。

## 3. 图鉴

图鉴是长期目标，因为它直接服务传播——
`我发现了 23 条轨道里的 17 条` 本身就是一句转发文案。

### 3.1 轨道图鉴

```
已发现  17 / 23
📚读书  🧱打工  🗂️考编  💼创业  🐭鼠鼠  🔧中专
🧘修仙  🎮电竞  🎤偶像  🎧说唱  🎰赌狗  🎀地雷系  ...
???  ???  ???  ???  ???  ???
```

未发现的显示 `???`，**计入分母**。明确告诉玩家还剩多少（SYSTEM §5 第 4 条）。

### 3.2 结局图鉴

同上，但有一个例外。

### 3.3 真结局的槽位（C7）

**真结局在图鉴里完全空白，不计入分母，达成前不留任何痕迹。**

不是显示 `???`，是根本不存在这一格。
达成后才出现一格，且**没有任何"恭喜解锁最高结局"的提示**，
它就静静地排在其他结局后面。

BRIEF C7 原文：游戏从不暗示它是"最好的"结局。
如果图鉴里有一个显眼的空槽，玩家就会去攻略它，
"在最贪的时刻主动放弃分数"会变成一次任务打卡，而不是一次选择。

## 4. seed 与分享（C6）

所有随机由 seed 驱动：天赋三选一、决策年落点、事件抽取、加更年数、保底轨道入口。

```
badhand.html?s=8F3K2Q
```

同一 seed + 同一 meta 解锁状态 → 完全相同的可能性空间。
**注意**：玩家的选择不在 seed 里，所以"重开同一条命"是重开同样的**牌局**，
不是重播同样的人生。这比单纯晒分强：`看你能在这条命里打到几分`。

meta 解锁状态会影响可能性空间，所以分享卡上要标注解锁进度，
否则别人跑同一 seed 得到不同结果会被当成 bug。

## 5. 存档

`localStorage` 单键存 JSON：

```js
{
  v: 1,                    // 存档版本，用于迁移
  material: 1240,          // 素材
  unlocked: { cast: [...], talent: [...], origin: [...] },
  found:    { track: [...], ending: [...] },
  stats:    { runs: 87, best: 6.4, cancelled: 31 },
}
```

无账号、无云同步、无网络请求（C8：`index.html` 双击即跑、不依赖网络）。
存档损坏时静默重置为初始状态并保留一个备份键，不弹错误对话框。


## 6. 任务 #7：构筑与元进度扩充（2026-08-02）

任务 #7 不另造货币、账号系统或网络分享服务，而是把现有 `DECK`、`CAST`、季末
`REWARD`、抽卡 `unlocked` 和结算 `found` 接成一条可重玩的闭环。

### 6.1 运行时元进度快照

开局由 UI 把当前存档的 `unlocked` 快照传入 `run.create({ meta })`。引擎只保存
本局需要的内容权限，不持有 localStorage：

```js
state.META = {
  unlocked: {
    cast: [...], talent: [...], npc: [...], track: [...],
    family: [...], personality: [...],
  },
}
```

`META` 只决定内容的**可能性空间**，不直接增加属性、收视或最终评分。旧调用不传
`meta` 时使用空快照，保持旧存档和测试 fixture 兼容。

### 6.2 构筑协同的唯一入口

`DECK` 仍然是当前季最多三张节目牌，`CAST` 仍然是逐局收集的人设牌。已有的
`deckSynergy()` 是唯一协同公式：

- 节目牌与事件 tag 命中，提升候选事件权重；
- 节目牌同 tag 达到两张/三张，产生“合拍/成套” chip 与有限 M 加成；
- 节目牌 track 与已持有 CAST track 相同，产生人设合拍 chip 与有限 M 加成；
- 协同必须继续出现在年度 breakdown 的 chips/mults 中，不能变成隐藏加分。

任务 #7 只补齐解锁后可进入的节目牌/奖励空间，不新增第二套乘数、牌面排序或
手动弃牌规则。高分构筑的再玩理由是把协同打得更完整，低分/腰斩的再玩理由是
用不同牌组和路线修正水位，真结局仍退出评分框架。

### 6.3 局内奖励与局外解锁

季末三选一仍只使用现有五类奖励：人设牌、观众、加更、属性、污点交易。
`META.unlocked.cast` 只优先影响可选的人设牌内容，不把抽卡结果变成开局直发的
数值；已有 `grant.cast` / `grant.scar` / `grant.flag` 事件契约不改变。

抽卡获得的 `unlocked` 在下一局产生三种可见但非数值的影响：

1. 已解锁天赋在 seed 驱动的天赋三选一中获得一个“档案位”机会；
2. 已解锁人设牌在季末人设奖励池中优先出现；
3. 已解锁轨道或 NPC 对应的档案节目牌/关系线牌可以进入路线 offers。

基础路线和既有隐藏路线不因没有解锁而消失；解锁只增加可选空间，不把首局变成
不可玩的锁门教程。真结局和结局文本不进入抽卡池。

### 6.4 发现图鉴

存档 `found` 在原有 `track`、`ending` 之外增加：

```js
found: {
  track: [...], ending: [...], event: [...], line: [...], plan: [...],
}
```

- `event`：本局 `state.EVT` 中实际播出的事件 id；
- `line`：本局 `ELINE` 已推进、完成、分叉或重逢的事件线 id；
- `plan`：本局 `PLANLOG` 选中过的节目牌 id。

结算时只做去重合并；开发模式不写入真实图鉴。UI 本阶段显示发现计数和未知量，
完整逐条图鉴页面留给任务 #8，不把计数伪装成内容解锁。

### 6.5 计划历史与 seed 重玩

`state.PLANLOG` 是跨季的只增数组，记录每次实际选中的 plan id；`ROUTE` 仍可在
季末清空。`state.seed` 是规范化后的本局编号，结算页必须显示它。

同一 `seed` + 同一 `META.unlocked` + 同一选择序列，必须得到相同的开局四项、天赋
候选、路线 offers、事件结果和抽卡结果。origin 重抽不得读取 `Date.now()` 或其他
墙钟值；分享仍是复制 seed 文本，不发送网络请求。不同解锁状态可以得到不同的
可能性空间，分享卡必须显示解锁进度，避免把差异误报为随机 bug。

### 6.6 反刷与迁移边界

- `unlocked` 只保存内容 id，不能保存属性增益、倍率或“已获得分数”；
- 重复抽卡继续按条目的 `dupValue` 转素材，不能通过重复解锁堆叠效果；
- `found` 和近期 seed 是记录，不参与年度公式；
- 旧存档缺少新增数组时按空数组迁移，失效内容 id 静默丢弃；
- dev 存档的奖励、解锁、发现和近期 seed 与正式存档隔离。

### 6.7 任务 #7 验收

1. 无解锁的旧开局与当前基线一致；
2. 相同 seed、相同解锁快照、相同选择序列可重放；
3. 解锁天赋/人设/轨道/NPC 至少分别改变一个后续内容入口；
4. `found.event/line/plan` 与实际本局日志、事件线、路线选择一致；
5. 高分、低分/腰斩、真结局和隐藏路线在结算或图鉴中留下不同记录；
6. 纯 `file://`、classic scripts、无网络和旧存档迁移仍通过。
