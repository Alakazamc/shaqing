# 模块：职业与家庭

> 上位：`docs/SYSTEM.md` §0、`docs/modules/04-tracks.md`、`docs/modules/11-origin.md`。
> 本模块补的是"文本不连贯"的**结构性**原因，不是文案质量问题。

## 0. 为什么需要它

纵切片跑通后暴露的问题：事件读起来是一串互不相干的碎片。

根因两条，都不是"文案写得不用心"：

1. **轨道太抽象。** `读书` / `鼠鼠` / `修仙` 是方向，不是身份。
   事件无法指涉"你现在是什么人"，只能写成泛化的场景。
2. **普通事件之间没有连贯性机制。** 只有事件线（`13-eventlines.md`）内部衔接，
   而事件线稀少。`EVT` 键存在但内容层几乎没用它。

**职业是让一条命读起来连贯的骨头**：它具体、持续、可被指涉、会晋升也会丢。

## 1. 职业阶梯

职业不是标签，是**有阶梯的身份**。

```js
{
  id: 'job_liushui',
  name: '流水线',
  emoji: '🔧',
  track: 'shushu',            // 归属轨道
  tier: 1,                    // 阶梯层级 1–4
  next: ['job_zuzhang'],      // 可晋升到
  entry: 'AGE>=17 & INT<=8',  // 入职门槛
  income: 1,                  // 每年 MNY 变化
  wear: { STR: -1 },          // 每年磨损
  socialWeight: 0.4,          // 计入社会位置（04-tracks.md §2）
  tags: ['职场', '苦熬'],
}
```

| 字段 | 作用 |
|---|---|
| `tier` | 1 打杂 → 2 熟手 → 3 骨干 → 4 头部。决定可用事件与收入量级 |
| `next` | 晋升链。**晋升由事件触发，不自动** |
| `income` / `wear` | 每年自动结算。这是"日子在过"的体感来源 |
| `socialWeight` | 让职业参与水位计算，于是失业是真的掉水位 |

### 1.1 失业与转行

- **失业**：`JOB` 置空，`income` 归零。失业本身是高桥段分事件
- **转行**：换到另一轨道的职业，`tier` 从 1 重来
- 转行的代价由贯彻乘数 `Com` 自然承担（`SYSTEM.md` §3.2），不需要额外惩罚

## 2. 父母：家庭不只是一个旗标

`11-origin.md` 原本的家庭只给旗标与场景。这不够——
童年期的连贯性完全依赖父母是谁。

```js
{
  id: 'fam_gongfang', name: '工房', emoji: '🏭', tier: 1,
  flags: ['f_gongfang'],
  scene: '厂区',
  parents: {
    father: { job: 'job_liushui', status: 'present' },
    mother: { job: 'job_liushui', status: 'present' },
    note: '作息一模一样',
  },
  income: 1,          // 童年期家庭给的每年 MNY
}
```

### 2.1 父母状况枚举

| `status` | 含义 |
|---|---|
| `present` | 在身边 |
| `absent` | 常年不在（外出务工、长期出差） |
| `gone` | 早年离开（不写死因，见 C4 克制原则） |
| `split` | 分开了 |
| `ill` | 身体一直不好 |

**父母职业决定童年事件池**，父母状况决定哪些事件可触发。
这样童年不再是通用的"上学放学"，而是有具体家境的童年。

### 2.2 父母是内容，不是数值

父母**不给属性加成**（与 `11-origin.md` §3 一致：家庭给可能性不给强度）。
父母给的是：

- 童年事件池的具体内容
- 职业倾向（父母是流水线，你更容易接触流水线）
- 后期的回响事件（父母老了、生病、去世）

## 3. 连贯性机制：三条硬要求

这是本模块要解决的核心问题。

### 3.1 每个季至少 4 条事件引用前情

引用方式（DSL 已支持，只是内容层没用）：

```
EVT?["e_s2_d02"]          你当年撕了那张表格
JOB=["job_liushui"]       你现在在流水线上
FLAG?["f_fuqin_bing"]     你爸的身体
NPCKNOWN?["npc_qishou"]   那个下棋的老头
```

**验收**：每季的 `include` 里引用 `EVT` / `JOB` / `FLAG` / `NPCKNOWN` 的事件数 ≥ 4。

### 3.2 回响事件（callback）

**定义**：`kind: 'echo'`，专门指涉多年前发生过的事，且只能靠 `EVT` 门槛进池。

```js
{ id: 'e_s4_echo_biao', kind: 'echo', season: 4,
  include: 'EVT?["e_s2_d02"] & AGE>=35',
  text: '同学群里有人提起那张表。他说当年他也签了，现在在南方。' }
```

回响事件是"这是我的人生"感觉的主要来源。每季配额见 §5。

### 3.3 职业必须被文本指涉

同一个事件在不同职业下应有不同文案。实现方式是**分职业的事件变体**：
同一 trope、同一结构，`include` 按 `JOB` 分流。

不做通用文案 + 占位符替换，因为那读起来仍然是模板。

## 4. 文案长度上限修正

`content/authoring.md` §2.9 原定事件正文 ≤ 60 字。**实测过短**：
一屏读完的约束满足了，但事件读起来是碎片，无法承载前情与后果。

修正：

| 位置 | 原 | 新 |
|---|---|---|
| decision 事件正文 | 60 | **140** |
| flavor 事件正文 | 60 | **90** |
| echo 事件正文 | — | **140** |
| 场景节拍 | 30 | **60** |
| 选项文案 | 14 | **20** |
| 死法 / 结局 | 200 | 200（不变） |

手机竖屏一屏仍能读完 140 字（约 5 行）。传播要求的是"截图里读得完"，
不是"短"——**过短反而没有可转发的内容**。

## 5. 内容配额（含连贯性）

| 内容 | A 期 | 首发 |
|---|---|---|
| 职业 | 8（4 轨道 × 2 阶梯） | 40 |
| 家庭（含父母） | 3 | 20 |
| echo 事件 | 6（每季 1–2） | 40 |
| 引用前情的事件 | 每季 ≥4 | 每季 ≥12 |

## 6. 一致性检查

补进 `content/README.md` §5.1：

1. 每个职业的 `next` 指向存在的职业，且 `tier` 严格递增
2. 每个职业的 `track` 存在
3. 每个 `entry` 条件可解析，且**不引用 `SEX`**（职业门槛性别中性）
4. 每个家庭的 `parents.father/mother.job` 指向存在的职业
5. `parents.*.status` 在枚举内
6. 每个 `kind: 'echo'` 事件的 `include` **必须引用 `EVT`**
7. 每季引用前情（`EVT`/`JOB`/`FLAG`/`NPCKNOWN`）的事件数 ≥ 4
8. echo 事件必须 `noRandom: false`（靠门槛进池，不靠指向）
