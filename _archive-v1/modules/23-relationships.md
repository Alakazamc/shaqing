# 模块：关系与恋爱纵切片

> 上位：`docs/SYSTEM.md` §0.5、`docs/modules/10-npc.md`、`docs/modules/13-eventlines.md`。
> 本模块只定义关系事件的运行时契约；文案仍遵守 `docs/content/authoring.md`。

## 1. 设计目标

关系不是一条可购买的好感度，也不是给 `CHR` / `SPR` 的隐藏奖励。玩家看到的是一个会改变安排的具体的人：

- **推进**：偶遇、约会、暧昧、承诺和现实压力各占一个跨年阶段；
- **可错过**：阶段之间超过 `maxGap`，事件线播出一次 `missEvent`，关系进入退场，不把没点到伪装成成功；
- **可分叉**：选项用 `fork` 进入另一条完整链。继续承诺与保持距离都必须有终点和独立后果；
- **可重逢**：退场后，事件线可在 `reunion.minGap` 年后用 `reunion.event` 恢复 NPC。重逢不是洗白，也不会重置旧旗标；
- **有回声**：`kind: 'echo'` 事件通过 `EVT` 引用关系节点，在多年后把共同账单、旧地址或未发送消息带回来。

## 2. 状态与 DSL

不新增顶层状态。`NPCAX[npcId]` 的形状为：

```js
{ axis: -10..10, stage: 1..N }
```

`stage` 是事件线走到哪一段，`axis` 是关系方向：负数为疏远/怨，正数为靠近，零为仍有来往但未定性。只有内容选项的 `relation` 会改变 `axis`；事件线推进不会自动加好感。

`NPCREL` 是派生 DSL 列表，例如 `NPCREL?['npc_lan:3']`。它只用于精确条件与调试展示；需要区间的内容使用明确旗标（如 `f_lan_commit`、`f_lan_breakup`），避免玩家计算隐藏数值。

选项可写：

```js
{ text: '把关系说清楚', relation: { npc_lan: 3 }, grant: { flag: ['f_lan_commit'] } }
```

`relation` 的 NPC id 必须存在，delta 必须是有限数字；引擎把轴钳在 -10…10。它不参与年度公式，只通过后续条件、退场、回响和 HUD 产生意义。

## 3. 事件线生命周期

```text
入口 → 约会/暧昧 → 承诺或分叉 → 现实压力 → 退场
                                      ↘ missEvent（超时）
退场 ── reunion.minGap 年 ──→ reunion.event → 再次在场
```

事件线可选字段：

| 字段 | 作用 |
|---|---|
| `missEvent` | 当前阶段超过 `maxGap` 时只触发一次的 `noRandom` 事件；触发后事件线完成，NPC 退场 |
| `reunion` | `{ event, minGap }`；主链/分叉/错过均完成后，条件通过才允许一次重逢 |
| `forks[].from` | 1-based 主链阶段；选项的 `fork` 是对应数组下标 |

`reunion.event` 必须通过 `NPCGONE` / `NPCKNOWN` 等条件确认前情。重逢后 `NPCGONE` 移除该 id，`NPCAX.axis` 保留，`stage` 继续记录旧关系走过的深度。

## 4. 内容写作边界

关系事件必须写具体安排，不写“你们感情变深了”：地铁末班车、共享账单、未读消息、父母电话、租约日期都可以成为阶段锚点。角色台词可以有判断，叙述层不替玩家判断谁对谁错。

同一条线至少要有：

1. 一个约会或相处入口；
2. 一个暧昧/承诺选择；
3. 一个现实压力节点；
4. 一个分手、失联或退场后果；
5. 一个跨年重逢或无法重逢的结果；
6. 一条 `EVT` 驱动的 `echo`。

关系事件的主要后果是旗标、关系轴、路线/轨道选择和后续文本。可以有正常年度收视，但不得把“恋爱成功”实现为无条件 `AUD` 或倍率奖励。

## 5. 自动验收

除通用事件线/NPC检查外，关系包必须满足：

- `relation` 只引用已登记 NPC，delta 为有限数字；
- 每个 `fork` 都由对应主链阶段的选项实际引用；
- `missEvent`、`reunion.event` 存在、`noRandom: true`，且不成为孤儿；
- `reunion` 只在 `NPCGONE` 条件下出现，并且每条关系线最多触发一次；
- 至少一个普通 echo 引用关系事件的 `EVT`；
- 关系轴变化可以在纯状态 JSON 往返后保持，旧 NPC 没有 `relation` 字段时仍能运行。

## 6. A 期纵切片

本期只加入一个 NPC，不扩张成恋爱数值模拟器。验收重点是：玩家能在三次选择后说出“我为什么和这个人走到这里”，能故意错过一条线，也能在另一局用不同选择看到分叉和多年后的重逢。
