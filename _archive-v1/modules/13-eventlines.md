# 模块：事件线与分叉退出

> 上位：`docs/SYSTEM.md` §3.2（贯彻乘数）、`docs/modules/03-events.md`（事件结构）。
> 本文定义"多阶段事件线"这一通用机制，以及它的**中途退出必须做成分叉而不是截断**。

---

## 1. 为什么需要"事件线"这一层

现有结构里有两种事件组织方式，都不够用：

| 已有 | 能力 | 不足 |
|---|---|---|
| 单点事件 | 一年一次，自包含 | 没有跨年的连贯性 |
| `branch` / `next` 链 | 一年内连播多个事件 | 仍在同一个脉冲里，跨不了季 |

**事件线（eventline）是跨年、跨季的多阶段结构。** 它是 NPC 关系、隐秘轨道深入、
以及一切"需要好几年才讲完"的内容的载体。

## 2. 数据结构

```js
{
  id: 'el_kuaxingbie',
  name: null,                  // 玩家可见名。敏感线为 null，不在任何 UI 露出线名
  stages: 4,
  entry: 'el_kx_s1',           // 入口事件 id
  // 每个阶段的事件 id，按顺序
  chain: ['el_kx_s1', 'el_kx_s2', 'el_kx_s3', 'el_kx_s4'],
  // 分叉：从某阶段岔出去的另一条完整链
  forks: [
    { from: 2, chain: ['el_kx_f2a', 'el_kx_f2b'], track: 'kuaxingbie' },
    { from: 3, chain: ['el_kx_f3a', 'el_kx_f3b'], track: 'kuaxingbie' },
  ],
  minGap: 1,                   // 阶段之间至少间隔几年
  maxGap: 6,                   // 超过则事件线自然沉默（不是失败）
  track: 'kuaxingbie',         // 所有阶段与分叉都归属同一轨道

  // 可选：把某些阶段以「场景」形式展开成多个节拍
  scenes: { 2: { beats: [...], signalRamp: null } },
}
```

`scenes` 字段让关键阶段**在同一年内展开成 3–6 个节拍**，
玩家沉进这件事而不是点一下就过。详见 `16-scenes.md`。

关系线还可以声明：

```js
missEvent: 'e_rel_missed',
reunion: { event: 'e_rel_reunion', minGap: 3 },
```

当前阶段超过 `maxGap` 时只触发一次 `missEvent`；主链、分叉或错过事件完成后，满足 `reunion.event` 的条件且经过 `minGap` 年，才会重逢一次。

**分叉点应当优先做成场景**：分叉是全局最重要的决策类型之一，
一屏一句话承载不住它。

关键字段是 `forks`。它不是"退出点"，是**从主链岔出去的另一条完整链**。

## 3. 分叉退出：为什么不能做成截断

先说清问题。`SYSTEM.md` §3.2 的贯彻乘数 `Com` 惩罚半途而废——
涉及 ≥3 条轨道且全部 `depth ≤ 2` 时强制罚到 `0.5`。

如果一条事件线的"中途退出"实现为**截断**（链断在第 2 阶段，深度停在 2），
那么退出在数值上就是更差的选择。对大多数题材这没问题，
但对跨性别这类**真实的、玩家可能有切身经验的**题材，
它意味着：**游戏在拿分数替一件真实的事表态。** 这违反 `C3`
——态度只能通过规则自我否定来表达，不能拿规则去评判玩家。

反过来给它豁免（"这条线不吃 `Com` 惩罚"）同样不行。特例本身就是表态，
等于游戏在说"这条我不敢评"，而且玩家一定会发现这个特例。

**解法是取消"截断"这个形态：退出即分叉，两条路各自都是完整的链。**

```
                    ┌─ el_kx_s3 ─ el_kx_s4        （主链走完）
   el_kx_s1 ─ s2 ──┤
                    └─ el_kx_f2a ─ el_kx_f2b      （分叉走完）
```

两条链**都能走到自己的终点**、**都推进同一条轨道的深度**、
**都能拿到该轨道的人设牌**。于是：

- `Com` 看到的是"一条轨道走到了它的某个终点"，不是"半途而废"
- 数值上两条路都不是惩罚项，游戏对选哪条**不表态**
- 玩家的选择仍然有后果（不同的人设牌、不同的标签、不同的水位走法），
  但后果是**不同**，不是**更差**

## 4. 分叉的三条硬规则

任何带分叉的事件线都必须满足，否则视为设计缺陷：

1. **分叉链有自己的终点事件。** 不允许"岔出去然后什么都没有"。
2. **分叉链推进同一条轨道的深度。** 深度增量可以不同，但不能为 0
   ——为 0 就等于变相截断，`Com` 会照样惩罚。
3. **分叉链数量 ≥ 1 个专属人设牌。** 否则构筑上仍然是亏的。

审查问句：**如果我是走分叉那条路的玩家，我拿到的东西是"另一套"还是"更少"？**
答案必须是前者。

## 5. 范例：跨性别事件线

这是本机制的第一个也是要求最严的应用。适用 `C4` 全部红线
与 `content/authoring.md` §4，另加本节的补充约束。

### 5.1 阶段语义

阶段只规定**发生了什么**，不规定如何评价。

| 阶段 | 内容定位 |
|---|---|
| s1 入口 | 一个不被解释的日常观察。**不设任何属性门槛**（见 §5.4） |
| s2 | 具体的一步。属性画像开始变化 |
| s3 | 外部世界的反应：家里、单位、观众 |
| s4 终点 | 稳定下来。属性画像迁移完成 |

分叉：

| 分叉 | 内容定位 |
|---|---|
| f2（从 s2 岔出） | 事情发生过，然后停在这里。终点是另一种稳定 |
| f3（从 s3 岔出） | 在外部压力之后的另一种安排 |

**主链终点与分叉终点都是"稳定"，不是"成功"与"失败"。**
两者各有专属人设牌、各推进 `kuaxingbie` 轨道深度、各带自己的标签。

### 5.2 文本基调

按全局叙述规范（`authoring.md`）：摄像机视角、零评价、笑点来自并置。
本线额外禁止：任何形式的"觉醒"叙事、任何形式的"后悔"叙事。
两者都是在替玩家定性。

register 参照（只示范语气，不是最终文案）：

```
✓  你把头发剪短了。理发师问要不要拍照，你说不用。
✓  你想，反正也没人注意。第二天有三个人注意到了。
✗  你终于成为了真正的自己。
✗  你开始怀疑这一切是否值得。
```

第二条示范了心理活动的正确用法：内心台词与外部事实并置，
叙述者不解释哪个对。

### 5.3 与振幅的交互，以及一条防滥用约束

属性画像迁移会改变水位曲线的走法，因此**在数学上确实会影响 `Amp`**
（`SYSTEM.md` §3.1）。这是机制的自然结果，不是刻意奖励。

但由此产生一个必须堵住的风险：**这条线不能成为高分捷径。**
否则玩家会为了分数去走它，题材被工具化。

约束：调参时把本线的期望收视贡献压在**普通轨道的同一区间内**
（`09-vertical-slice.md` §5 增加对应检查）。它可以是一条有分量的线，
不可以是一条划算的线。

### 5.4 为什么入口不设属性门槛

如果入口条件写成 `SPR<3`（心低），游戏就在暗示这件事与精神状态有因果关系
——这是病理化。入口只能是纯剧情链触发（`04-tracks.md` §4.1 已定）。

注意这与"性别影响属性"不冲突：**开局性别给属性画像**，是出身设定；
**把轨道入口挂在某个属性上**，是在给因果关系下判断。前者做，后者不做。

---

### 5.5 延寿型超自然与科幻事件线

寿命延长不使用新的 `effect` 键。引擎已有 `lifespan` 运行时字段，内容层唯一兑现方式是：

1. 事件线主链或分叉走到终点；
2. 终点选项授予带 `lifespan` 数值的人设牌；
3. `applyOption` 在授予人设牌的同时把数值加到当前寿命上限。

主链与分叉应给出不同幅度的延寿和不同代价，不能把延寿做成所有选择都拿到的白送奖励。
魔法线体现“看见得更多，但越来越不像普通人”，科幻线体现“把未来存起来，同时把现在交出去”。
两条线都必须有至少一个 flavor 和一个 `EVT` 回响，证明延寿改变的是整条人生而不是一张终点卡。

## 6. 其他适用事件线

分叉退出机制不是为单一题材造的。以下同样适用：

| 事件线 | 分叉的含义 |
|---|---|
| NPC 关系线 | 继续深交 / 就此淡了（两者都推进关系轴，方向不同） |
| `yaowu` 线 | 两条链都通向各自的稳定态，均不做成奇观 |
| `dilei` 线 | 同上 |
| 修仙线 | 继续筑基 / 下山（下山是另一套人设牌，不是失败） |
| 考编线 | 继续考 / 上岸后发现另一件事 |

**"修仙线可以下山"这一条尤其重要**：它证明分叉机制是通用设计而非为敏感题材开的特例。
玩家在修仙线上体验过"岔出去也是一条完整的路"，
再遇到敏感题材时就不会把分叉读成认输。

## 7. 一致性检查

补进 `content/README.md` §5 的可执行断言：

1. 每条事件线的 `chain` 中所有事件存在，且均 `noRandom === true`
2. 每个 `forks[].chain` 非空，且最后一个事件是终点事件（无 `next`）
3. 每个 `forks[].from` 落在 `1 … stages-1` 范围内
4. 主链终点与每条分叉终点**各自至少授予 1 张人设牌**
5. 每条分叉的轨道深度增量 **> 0**
6. `minGap ≤ maxGap`，且均 ≥ 1
7. 敏感题材事件线（`kuaxingbie` / `yaowu` / `dilei`）的 `name` 必须为 `null`
8. 敏感题材事件线的入口事件 `include` 条件**不得引用任何属性键**
   （只允许引用 `FLAG` / `EVT` / `AGE` / `SEASON`）

第 8 条是把 §5.4 的原则做成机器可验证的规则，
避免它随内容量增长被无意破坏。
