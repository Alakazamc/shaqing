# 梗词库（lexicon）

> 上位：`docs/BRIEF.md` C5。运行时镜像为 `content/lexicon.js`。

## 0. 一个必须写在最前面的前提

**这张表的"当期热度"判断不可靠，需要人工复核。**

写这份文档的模型语料有时间截点，对"现在群里在说什么"没有可靠感知。
凡是标了 `热度待核` 的词条，都必须由实际泡在对应圈层的人过一遍再进 `lexicon.js`。

这不是免责声明，是流程要求：**C5 反的是"老人味"，
而一个语料过期的模型正是老人味的最大来源。**
表结构和替换机制是可靠的，具体词条不是。

---

## 1. 为什么要独立一层词库

C5 已定：少用被官媒和 HR 用烂的泛梗，以亚文化圈层内部梗和新梗为主，
且梗跟随玩家所处轨道投放。

三条工程理由：

1. **可替换** — 梗会过期。集中在一层，过期时只改词库不改事件。
2. **可分圈层** — 事件文案按轨道 `lexiconScope` 取词，二次元轨道吃二次元梗。
3. **可隔离风险** — 高风险梗只出现在可替换槽位，绝不进机制名称。

## 2. 字段定义

```js
{
  id: 'lx_pofang',
  term: '破防',
  scope: 'common',          // 圈层，见 §3
  risk: 'low',              // 过期风险，见 §4
  hotness: 'settled',       // settled | current | 待核
  usage: '用于形容被戳到痛处后的失态',
  audience: '全体玩家',      // 实际受众/圈层，不等同于 scope
  expiryRisk: 'low',         // low | mid | high，供审计读取
  replaceable: true,         // 是否能只替换词条而不改事件机制
  reviewStatus: 'confirmed', // confirmed | pending
  slot: ['text', 'review'],  // 允许出现的槽位，见 §5
  note: '已沉淀进日常汉语，不算圈层梗',
}
```

## 4. 过期风险（risk）

| 等级 | 判据 | 允许出现的位置 |
|---|---|---|
| `low` | 已沉淀进日常汉语，三年后仍能看懂 | 任意文案槽位 |
| `mid` | 圈层内稳定使用，圈外可能不懂 | 事件正文、短评 |
| `high` | 当期热梗，半年后可能就尬 | **仅** `review`（短评）槽位 |

`high` 只允许进短评，因为短评是整个游戏最容易整批替换的部分——
它是模板化生成的，不与任何事件逻辑耦合。

**任何等级都禁止进入**：轨道 id、人设牌 id、污点牌 id、字段名、机制名称、结局名。
所以人设牌叫 `cast_chouxiang`（抽象怪）而不是某个当期热梗的音译。

## 5. 槽位（slot）

| 槽位 | 说明 | 替换成本 |
|---|---|---|
| `text` | 事件正文 | 中（需重读上下文）|
| `option` | 选项文案 | 中 |
| `review` | 结算页短评 | **低**（模板化）|
| `title` | 剧名槽位词 | 低 |
| `castname` | 人设牌**显示名** | 高（玩家会记住）|

`castname` 只允许 `low` 风险词条。玩家会在截图里晒人设牌，
牌名过期比事件文案过期难看得多。

## 6. 老人味黑名单

以下词**不得作为圈层梗使用**。它们已被官媒、HR、营销号用烂，
写进去像市场部文案而不是群友（C5 原话）：

```
内卷  躺平  社死  破圈  赋能  闭环  抓手  颗粒度
奋斗  正能量  逆袭  emo  YYDS  绝绝子  夺笋
```

例外：`破防`、`大冤种` 这类已经真正沉淀进日常汉语的，标 `common` / `low` 可用，
但**不算圈层梗**，不能用来充当"圈层内部梗"的配额。

判定方法：**这个词有没有出现在过去一年的地方政务号推文里？**
出现过 → 黑名单。这个判据比"我觉得它还行"可靠得多。

---

## 7. 不使用梗的地方

以下位置**一律不用任何梗**，用平实中文：

- `yaowu` 轨道的全部文案（C4：不猎奇、不浪漫化）
- 所有自毁类事件
- 真结局「稳定的好日子」的全部文本（C7：全游戏唯一一段真诚文字，
  一个梗都不能有——梗是表演的一部分）
- 死亡描写

这条不是保守，是基调一致性：**梗是"给观众看"的语言。**
在游戏最不表演的地方用梗，会直接摧毁 C7。

## 9. 维护流程

1. **季度复核** — 每季度过一遍 `high` 与 `mid` 词条，过期的直接替换。
   `low` 词条三年一核。
2. **替换只改词库** — 事件文案引用 id，不硬编码词。
   替换词条不需要碰任何事件文件。
3. **新增走审查** — 新词条必须填齐 `scope` / `risk` / `hotness` / `slot`，
   并过一遍 §4 的位置限制与 §6 的黑名单判据。
4. **配额监控** — `common` 占比不低于 55%，否则圈外玩家看不懂；
   不高于 70%，否则失去圈层质感、退回泛梗。

## 4.1 词条元数据与复核状态

每条运行时词条还必须填写四个审计字段：

| 字段 | 取值 | 作用 |
|---|---|---|
| `audience` | 自由文本 | 写明真正使用这句话的受众，不把 `scope` 当成受众证明 |
| `expiryRisk` | `low` / `mid` / `high` | 给批量替换脚本读取的过期风险镜像，必须与 `risk` 一致 |
| `replaceable` | `true` | 明确这条词只属于可替换文案层，不得成为机制依赖 |
| `reviewStatus` | `confirmed` / `pending` | `pending` 只能作为候选槽位，未复核词不得进入核心叙述 |

A 期新增的 `campus`、`workplace`、`esports`、`xianxia`、`scifi`、`lingyi` 候选词统一标为 `pending`，并保留在词库中供后续人工替换；当前新增事件继续使用平实中文，不把待核词硬编码进叙述层。这样“有词库”与“已经验证过圈层语感”不会被混为一谈。
