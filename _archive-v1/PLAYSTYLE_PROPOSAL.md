# 玩法重构提案：人生编排

> 状态：#3 最小纵切片已实现，正在以实测数据调节节奏；本文仍不替代 `docs/SYSTEM.md`，机制变更必须同步模块文档。
> 目标：让玩家回答“这一季我要把什么播出来”，而不是只回答“这一年选哪个属性加成”。

## 1. 不变的硬约束

1. 仍然只有点击：点击编排节点、点击事件选项、点击继续；没有拖拽、手牌排序、数值分配或小游戏。
2. 年度公式 `R = round(B × M × A × F)`、`Amp/Com/Iro`、五季完整播出、真结局四条件不改。
3. 人设牌仍是被动牌，玩家不手动“打出”；分数仍衡量故事戏剧性，不衡量道德正确或生活幸福。
4. 所有随机仍由 seed 驱动；隐藏轨道在文本和普通预览中不直接泄底；引擎继续零 DOM、`file://` 可运行。

## 2. 从参考作品提取什么

| 来源 | 提取的机制 | 明确不复制 |
|---|---|---|
| Balatro | 被动牌之间的条件协同、筹码/倍率分层、成型后数字爆发 | 手牌、弃牌、商店和具体牌面 |
| Slay the Spire | 当前节点与后续节点预览、路线风险取舍、不同路线的节奏 | 战斗、能量、敌人和关卡结构 |
| Reigns | 一次点击就产生叙事后果，选项短、反馈快 | 左右滑动及其内容形式 |
| Luck be a Landlord | 标签集合、有限编排槽位、凑套与混搭的取舍 | 自动老虎机、具体符号和经济模型 |

## 3. 一局的目标与循环

玩家没有单一“通关答案”。一局的可见目标分三层：

- **眼前目标**：让本季收视达到续订线；超过 2× 争取加更和高档季末奖励。
- **构筑目标**：在有限的季内编排槽位里形成一套互相咬合的节目标签，或故意做出有张力的混搭。
- **长线目标**：播到 S5，留下一个高分、低分、腰斩、隐藏轨道或无评分结局，推动下一局的内容池与图鉴。

```text
季首看续订线与三格路线预览
  → 本季每个决策年先选一个编排节点
  → 节点按标签/轨道组装本季事件池，并显示风险预览
  → 事件出现后仍从 2–3 个后果选项中点一个
  → 年度收视推进续订线；人设牌按当前编排触发协同
  → 季末：续订 / 加更 / 腰斩，再选一个季末奖励
  → 清空本季编排，进入下一季；S5 后按原公式结算
```

编排选择取代原来“点继续让随机事件出现”的那一次点击，不额外制造一个菜单脉冲；事件选项仍是下一次点击。目标是让决策脉冲数不增加，而决策的可预见性增加。

## 4. 季内路线：编排节点

### 4.1 节点形态

每季的决策点数量沿用 `SYSTEM.md`：S1 2、S2 2、S3 4、S4 3、S5 2。每个决策点显示 2–3 个编排节点，玩家选一个，未选节点离开本季路线。HUD 同时显示“本季编排 2/4”和接下来 1–2 个候选节点。

节点不承诺一个固定事件，而是改变下一次抽取的**候选池、权重和风险**。固定分水岭、入职保底、死亡和已经到期的事件线仍优先，不被路线选择破坏。

### 4.2 四类基础节点

| 节点 | 低保信息 | 代价与潜力 | 典型池变化 |
|---|---|---|---|
| 稳播 | 低风险、观众稳定 | `B` 较低，偏 `AUD/SPR`，不容易出污点 | 普通生活、职业、家庭 |
| 追热 | 高风险、高桥段 | `HOOK` 上升，`AUD` 波动，可能拿污点 | 网络、失控、热点 |
| 追线 | 中风险、路线明确 | 提高某条合资格事件线与对应轨道的机会 | 关系、职业或隐秘线 |
| 混剪 | 中高风险、结果分散 | 同时吃两类标签；成套奖励低，振幅机会高 | 两个不相同的标签池 |

节点的显示文案只描述节目动作和可见代价；隐藏轨道显示为“未知信号/某种可能性”等中性提示，发现后才显示名称。节点不是道德建议，稳播不会被表扬，追热也不会被嘲笑。

### 4.3 节点数据契约（提案）

```js
{
  id: 'plan_hot', label: '把这一季做得更响', kind: 'hot',
  track: 'wanghong', tags: ['网络', '失控'],
  risk: 'high', audience: 'swing', cost: ['HOOK', 'SPR'],
  poolTags: ['网络', '失控'], lineBias: ['el_pingtai'],
  hidden: false, season: [2, 3, 4]
}
```

`risk/audience/cost` 是玩家能看到的区间提示，不是精确收视预测；`poolTags/lineBias` 只供引擎选池。内容 schema 仍采用追加式注册，不能让节点覆盖计分公式或季末规则。

## 5. 年度事件牌组

“牌组”不是玩家要整理的手牌，而是本季已选编排节点组成的最多 3 张**节目牌**。每张节目牌只记录 id、标签、轨道倾向和本季槽位；点击节点即加入，不提供拖动、移除或排序。

- 同类标签达到 2 张：形成“合拍”，匹配事件的出现权重上升，并在年度分数行显示一次协同。
- 同类标签达到 3 张：形成“成套”，匹配事件获得小幅桥段/选项质量提升，但疲劳仍照常生效。
- 三张标签完全不同：不触发成套，却保留混搭带来的路线变化和振幅机会；不能被系统统一判成坏牌。
- 每季结束后节目牌清空；跨季的长期贯彻仍由 `TRACK`、`CAST`、`TAG` 和事件线记录承担。

初版不另造一套分数公式。节目牌只做三件事：筛选/加权事件池、决定风险预览、向已有 `collectChips/collectMults` 提供有限的协同筹码。疲劳、观众权重、三乘数和污点乘法仍由原模块负责。

### 5.1 建议状态变更

在更新 `SYSTEM.md` 后新增两个纯数据字段，不再继续散落临时顶层字段：

```js
DECK: [],                         // 当前季节目牌 [{id, track, tags}]
ROUTE: { season: 1, slot: 0, offers: [], picked: [], risk: 0 }
```

`DECK` 最多 3 项，`ROUTE.picked` 只保留本季选择历史；seed、解锁状态和选择序列仍决定同一局的可复现空间。实现前需补状态 clone、存档无关测试和旧存档默认值迁移。

## 6. 人设牌协同

现有 `CAST` 继续提供基础 `addDrama/addMult/xMult`。现有 `card.track` 不再闲置：当当前节目牌或节点轨道与人设牌一致时，牌获得一次“合拍”标记。

- 0 张匹配牌：只用牌的基础效果。
- 1 张匹配牌：显示“合拍”，给很小的额外筹码或事件权重；不直接改变评分公式。
- 2 张以上匹配牌：显示“阵容成型”，允许该牌的内容效果放大，但设置全局上限，保证单牌和单季不会把 `M` 失控推高。
- 一张牌只能按当前节点匹配一次；同一牌的 `lv` 仍按原规则放大，重复获得不是额外触发漏洞。

协同的玩家反馈必须包含：匹配了哪张牌、改变了哪类候选、给本次 `B/M` 增加了什么。没有反馈的隐藏加成不计入实现完成度。

## 7. 风险预览与失败反馈

每个节点在按钮内固定显示四行短信息：`风险：低/中/高`、`收视：稳/波动/爆发`、`代价：属性或戏瘾轴`、`可能播出：普通/关系/未知`。它告诉玩家取舍，不伪装成精确算命。

季末结算必须把失败写成可行动的账单：`本季 18,400 / 30,000，差 11,600`，然后明确 `AUD 38→19`、`注水 +1`、`下季续订线 ×1.5`。腰斩仍不截断人生；吃污点的构筑可以把失败转成优势，符合 C3。

高风险节点不是“正确路线”，低风险节点也不是“无聊惩罚”。一路稳播会缺少振幅和高价收手，一路追热会撞疲劳、腰斩和污点；玩家需要根据自己的 `CAST/DECK` 决定承担哪种风险。

## 8. 分数的用途闭环

玩家在 HUD 看到 `本季收视 / 续订线 / 超额倍数`，在年度分数行看到 `B、M、AUD、F` 的来源，在节点上看到风险，在季末看到奖励档位。

闭环固定为：

```text
年度收视 → 推进续订线
          → 续订/加更/腰斩
          → 季末奖励改变下一季 CAST/DECK/寿命/观众
          → 终局总收视与 Amp/Com/Iro 生成评分
          → 总收视转素材，评分与本局主题影响抽卡权重
          → 抽卡/素材定向解锁改变下一局可见内容，不改变基础数值
```

不新增局内货币；素材是局外慢速解锁资源。评分不直接兑换强度，只负责结算展示、抽卡档位倾斜和传播比较。真结局仍显示“—”，不因路线牌或人设牌直接获得。

当前实现把这条闭环放到了玩家眼前：年度日志显示 `B/M/A/F`，HUD 显示本季收视到续订线，季末解释续订/加更/腰斩，结算页显示总收视、三乘数、评分和素材来源，抽卡页显示评分与主题池的作用。首次轨道/结局和腰斩也会转成素材；抽卡结果写入解锁记录。解锁记录真正过滤下一局池子的规则留给元进度阶段，避免把尚未实现的效果当成分数用途。

## 9. 最小纵切片实现与验收

纵切片已接入现有纯前端循环，目标是证明“本季编排会改变这一季怎么播”，而不是先扩写更多事件：

- `content/plans.js` 注册 6 个路线节点：稳播、学习、追热、追线、未知信号、混剪；`content/manifest.js` 已纳入，`seal` 会校验季节、风险、轨道、标签、事件线偏置、gate 和 effect。
- `state.js` 增加纯数据 `DECK/ROUTE`；节目牌每季最多 3 张，季末提交、奖励和复活均清空，旧存档缺字段时由运行时补默认值。
- `run.js` 在决策年直接接受 `{type:'plan', index}`：路线点击后立即抽事件，不增加旧的“继续揭示”空点击；牌组标签提高候选权重，轨道与 `CAST.card.track` 产生有限可见协同，`decisions.byTrack` 记录路线/选项贯彻。
- `app.js` 与 `index.html` 显示风险、收视倾向、代价、可能播出、当前节目牌和合拍人设；隐藏路线统一显示“未知信号”，不把真实轨道名送进可见预览。
- 普通过场允许在同一脉冲携带第二条 flavor，日志逐条呈现且逐条结算；这是点击预算压缩，不改变年度公式或场景逐拍深度。

验收结果：

1. 同 seed、同出身的 `plan_steady / plan_study / plan_hot` 会改变 `DECK`、风险、`TRACK`、`decisions.byTrack` 以及实际 `chips/mults`；相同选择序列仍可复现。
2. 路线选择复用原决策年揭示位置，没有新增空点击；季末提交、`applyReward`、`commitRevive` 均不会把旧季牌组带入下一季。
3. `card.track` 匹配节目牌时可见“合拍·人设”筹码/倍率；不匹配时仍保留基础牌效。
4. 隐藏节点在可达决策年显示“未知信号”，可见字段不包含 `xiuxian` 或 `el_xiuxian`。
5. `node test/validate-content.mjs`、`node test/run-tests.mjs`、`node test/loopcheck.mjs`、`node test/jobrate.mjs`、`node test/browser-check.mjs` 全部通过；浏览器 smoke 为 11/11，file://、本地脚本、零外部请求均成立。

| 策略 | 局数 | 评分中位数 | 总脉冲中位数 | 估算时长中位数 | 腰斩率 |
|---|---:|---:|---:|---:|---:|
| random | 200 | 3.6 | 62 | 155 秒 | 74.5% |
| greedy | 100 | 5.1 | 63 | 157.5 秒 | 7.0% |

时长已落在熟练局 ≤170 秒目标内；总脉冲仍比 `SYSTEM.md` 的 45–60 中位数目标高约 2–3 次，且场景中位数为 1。这个偏差暂不通过改评分公式或削短场景掩盖；下一轮应单独处理决策事件/强制事件与 flavor 压缩，并补足场景触发率。

## 10. 暂不做的东西

暂不做拖拽牌组、局内商店、自由调整属性、复杂路线大地图、玩家手动移除节目牌、评分公式重写、永久数值强化、真结局提示和强制抽卡动画。先让三类节点与人设协同成立，再扩恋爱、职业、普通生活和异常内容。
